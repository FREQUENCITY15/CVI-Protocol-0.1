# Contributing to CVI

CVI improves when people find ways it can fool itself.

Useful contributions include:

- a capability claim that breaks the current protocol;
- a confound not covered by the intervention guide;
- a counterexample where a system passes the gates for the wrong reason;
- a literature predecessor that narrows or defeats a novelty claim;
- a metric boundary case;
- a cheaper control that isolates the same mechanism;
- an implementation of the protocol in an existing eval framework;
- replication of the historical pilot;
- a negative result.

## Evidence conventions

Please distinguish:

- **OBSERVED** — direct evidence;
- **INFERRED** — interpretation;
- **UNRESOLVED** — evidence insufficient.

## Preferred issue shape

When challenging a CVI claim or protocol rule, include:

1. the exact claim/rule;
2. the failure mode or alternative explanation;
3. a minimal counterexample if possible;
4. the cheapest discriminating test you can think of;
5. what result would change your mind.

## Anti-goals

This project is not improved by:

- turning CVI into a single prestige score;
- hiding failed experiments;
- treating more compute as a substitute for better controls;
- claiming novelty before collision with prior work;
- treating system-level performance as model-only capability without isolation;
- using “causal” as decoration.
