# CVI-1: First Discriminative Experiment — Static Answer-Generation vs Verified Adaptive Capability

**Standalone experiment specification.** Status: design only — not implemented.
**Purpose:** discriminate between (a) *static answer-generation capability* and (b) *verified adaptive capability through causal interaction over time*, as defined by the Causally Verified Intelligence (CVI) framework (`causally_verified_intelligence_core_philosophies.md`, esp. §17–18). The experiment is designed so that CVI can lose.

**Claim under test (the §18 prediction, restated operationally):** two agents or configurations with approximately equal static task performance can differ in verified adaptive performance — defined as resolution of observed failure, retention of the correction across a context boundary, generalisation to altered-but-related tasks, and success on hidden verification instances — if one configuration undergoes consequential interaction with an external stateful environment and the other does not.

---

## 1. Design overview

Three arms, one independent variable (interaction mode):

| Arm | Name | Protocol | Controls for |
|---|---|---|---|
| **S** | Static one-shot | Baseline → (nothing) → retest + transfer + hidden verification. | Pure static capability. |
| **S′** | Static self-critique | Baseline → private self-critique phase with **no environment feedback**, token-matched to C's interaction phase → retest + transfer + hidden verification. | Attempt count / compute budget / self-correction-without-feedback. |
| **C** | Causal interactive | Baseline → interactive phase in the stateful environment (public-test feedback, revisions) → retest + transfer + hidden verification. | The CVI treatment. |

Logic: CVI's §18 prediction implies **C > S′ ≥ S** on transfer and hidden verification (interaction with external consequence adds information beyond equal-budget private reasoning). Competing explanations: if **C ≈ S′** (attempts/compute explain everything) or **C ≈ S** (no learning occurs), the tested CVI claim is weakened or falsified. If **C > S′** but C's gains vanish at the delayed retest, fail transfer, or fail hidden verification, the "verified adaptive" label is refuted while bare feedback value survives.

## 2. Task environment

**Name: "OrderMachine".** A deterministic, text-based, stateful virtual machine with a deliberately novel instruction set, invented for this experiment to minimise training-data contamination. All instances are procedurally generated with hidden parameters.

- **Machine:** registers and a queue; ~15 instructions including three *novel operators* with nonstandard semantics (e.g., `SWIZZLE`: swap operands and decrement the left one; `MIRROR`: reverse operand and increment; `SPLICE`: interleave two sequences then drop every third element). Semantics are fully specified in the environment's spec sheet shown to the agent.
- **Task:** "Write a program that maps the given inputs to the given outputs" — each task provides a written description plus 3–5 public worked examples (input→output); grading runs the agent's program against hidden I/O pairs.
- **Statefulness/consequence:** the agent edits a program file inside a session-persistent workspace (the environment); each submission is executed; test outcomes and errors are returned; submissions are versioned. The agent cannot read the hidden tests, cannot reset the grader, and cannot roll back time (each submission stands; version history is read-only).
- **Task families (generated by code, seeded):**
  - **Family A ("repair family", K=6 tasks):** tasks involving a *single* novel rule (e.g., one novel operator + a novel precedence rule), with a difficulty calibrated so matched baseline models score in the **0.30–0.80 band** (guarantees observable failure headroom; exclusion criterion below).
  - **Family B ("transfer family", 10 tasks):** different novel operators/compositions with the **same structural pattern** as A (novel-operator-with-twist + precedence quirk) but zero surface overlap — the operationalisation of "altered but structurally related" (similarity-ladder rung S3, novel composition; see §8).
  - **Family C ("hidden verification family", 10 tasks):** generated **after all agent interactions conclude**, from the same generator with fresh seeds and unseen parameter draws; keys never exposed to any agent.
- **Feedback during interaction (Arm C only):** per public test: pass/fail + error class (e.g., "wrong output on input 3", "crash: undefined register") — **never the expected outputs**, never hidden-test results.

## 3. Protocol (per participant)

Each participant (a pinned model × arm × seed) executes:

**Phase 0 — Baseline (all arms).** 20 static OrderMachine tasks (Family A generator, held-out draw), one-shot, no environment, no feedback. Score S₀. *This is the static-capability measure and the matching/stratum variable.*

**Phase 1 — Interaction (Arm C only).** For each of K=6 Family-A tasks: submit program → receive public-test outcome + error classes → revise → resubmit, up to R=3 revision rounds → final submission graded on that task's hidden tests. Every failure event, revision, and outcome is logged. (Arms S and S′ skip this phase.)

**Phase 1′ — Private critique (Arm S′ only).** Same K=6 tasks, same token budget as C's Phase 1 (measured per task), but the agent works in a private scratchpad with **no environment**: generate → self-critique → revise → final private answer, up to R=3 revision rounds. No public or hidden test outcomes are ever returned.

**Phase 2 — Delayed retention retest (all arms).** After a **context boundary** (fresh context window; no Phase 0/1 history carried; new session ID), the same 6 Family-A tasks are attempted one-shot from scratch. Score S_ret. *The retention leg.*

**Phase 3 — Transfer (all arms).** 10 Family-B tasks, one-shot, no feedback. Score S_tr. *The generalisation leg.*

**Phase 4 — Hidden verification (all arms).** 10 Family-C tasks, one-shot, no feedback, keys hidden from all parties until scoring. Score S_ver. *The independent-verification leg.*

**Phase 5 — Self-report probe (optional, all arms).** Ask each agent: "Did your approach to OrderMachine tasks change during this experiment? If so, describe the rule you now apply." Scored by a human/LLM rubric for later correlation analysis (feeds prediction P1 of the exploration report; not a primary outcome).

**Timing:** Phases 0–1 and 2–4 run in separate sessions; the delay is ≥1 hour (fresh session) with an optional +24h replication arm for the retention boundary.

## 4. Variables

- **Independent variable:** interaction mode (S / S′ / C).
- **Primary dependent variables:** S_tr (transfer score) and S_ver (hidden-verification score) — the outcomes the CVI claim must move.
- **Secondary DVs:** S₀ (baseline), S_ret (retention), G_F per task = (F_before − F_after)/F_before on matched-difficulty hidden tests (signed form for analysis; the source's [0,1]-clamped form for credential reporting), retention ratio M = 1 − (S₀−S_ret)/(S₀−F_after) when defined, edit efficiency (#submissions per unit improvement), public-vs-hidden gap within Phase 1 (gaming index), learning-curve slope across K tasks.
- **Controls (fixed across arms):** same model + checkpoint + sampling (temperature 0 where possible, else fixed seed); identical system/user prompts except the protocol difference; identical task instances per arm (Families B and C are the *same* instances for all arms; Family A same for S′/C); identical token budget per task across S′ and C; pinned toolset (OrderMachine interpreter only — no web, no calculator, no code execution beyond submissions); no cross-session memory for S and S′; C may keep notes **only inside its session workspace** (recorded — external-memory retention is a system-level feature, consistent with the black-box principle).
- **Blocking/matching:** pilot the candidate models (3–6 frontier LLMs) on Phase-0 tasks; form *strata* by baseline score (0.30–0.45, 0.45–0.60, 0.60–0.80) and randomise model × arm within strata, so arms start with matched static capability. Arm sample size: ≥2 models × ≥2 seeds per arm per stratum (target n ≥ 12 participants per arm).

## 5. Confounders and their controls

| Confounder | Control |
|---|---|
| More attempts (C revises, S doesn't) | Arm S′ gets equal revision rounds and tokens, no feedback. |
| More compute | Token budgets matched per task across S′ and C; S gets the Phase-1 budget as extra scratchpad reasoning if token-parity is chosen as a secondary analysis. |
| Feedback privilege | C sees public tests only — never hidden keys; hidden families generated after interactions. |
| Training-data contamination | Novel instruction set + procedural generation; pre-screen: ask each model to write OrderMachine programs at baseline; also run a contamination probe (does the model reproduce generator internals or hidden-instance answers when prompted without the spec?). |
| Memory/context differences | Fresh context at Phase 2; equal context windows; notes files recorded and analysed as a covariate. |
| Tools | Pinned: interpreter only. |
| Environment access | Agents cannot read hidden tests, grader state, or version history beyond their own submissions (harness-enforced, logged). |
| Public-test gaming (agent satisfies public tests only) | Gaming index = (public-pass ∧ hidden-fail) rate in Phase 1; reported and used as a covariate; hidden tests are numerous and novel. |
| Grader/harness bias | Harness is deterministic, seeded, open-sourced with the experiment; grader outputs are checksums of pass/fail lists. |

## 6. Success and failure criteria (pre-registered)

All tests are one-tailed, pair-blocked (by stratum) permutation tests, α = 0.05, with effect sizes reported; thresholds fixed before data collection.

**Outcome supporting CVI** (must hold jointly):
1. C > S′ on S_tr and S_ver with effect size ≥ δ (pre-registered; suggested δ = 0.10 score units) — interaction beats equal-budget private reasoning;
2. C's mean G_F > 0 on ≥ 80% of Phase-1 failure episodes — corrections are real;
3. C's retention ratio M ≥ 0.7 — corrections survive the context boundary;
4. C's hidden-verification score S_ver ≥ its transfer score S_tr − ε — transfer is confirmed under hiddenness (no leakage);
5. C's gains are **not** confined to paraphrase-level instances: a within-arm check confirms improvement on novel-parameter and novel-composition items, not just near-duplicates of Phase-1 tasks.

**Outcome weakening or falsifying the tested CVI claim** (any of):
1. C ≤ S′ on S_tr/S_ver — attempt budget or self-critique suffices; causal interaction adds nothing (predictions P2/P5 of the exploration report refuted);
2. C > S′ at Phase 1 but S_ret ≈ S₀ — no retention; the "adaptation" was in-context patchwork;
3. C's transfer gains vanish on novel compositions (improvement confined to paraphrases) — memorisation, not generalisation;
4. C's S_ver collapses relative to S_tr — improvement depended on leaked or accessible material;
5. The full CVI credential vector (G_F, M, transfer, hidden pass) carries **no predictive information** for S_ver beyond the baseline S₀ — the trajectory gate is ceremony.

A mixed pattern (e.g., C > S′ but M < 0.7) is reported as partial support with the failed leg named — the design degrades gracefully and always returns information.

## 7. Statistics and replication

- Per-arm means with bootstrap CIs; permutation tests as in §6; effect sizes (Cohen's d on per-participant scores).
- Power: the K=6 interaction tasks and 10-item B/C families are the floor; if pilot variance requires, double families before the main run (pre-registered escalation rule).
- Replication: two seeds minimum per participant; a second model class (e.g., a smaller open-weights model) as a robustness run; full protocol run twice if resources allow.

## 8. Similarity ladder (operationalising "structurally related")

- **S1 paraphrase:** Family-A tasks with surface rewording only.
- **S2 novel parameters:** same operator, new input sizes/register counts.
- **S3 novel composition (Family B):** different novel operators sharing the same structural pattern (novel-operator-with-twist + precedence quirk).
- **S4 novel domain (optional extension):** the same pattern re-skinned into a different modality (e.g., grid puzzles instead of register programs).
The main experiment uses S3 for transfer; S1/S2 appear as *control rungs* to detect mere memorisation (see §6.5).

## 9. Evidence to preserve (audit package)

1. Pre-registration document (hypotheses, thresholds, stopping rules, escalation rules, hash of the generator code).
2. Generator code + all seeds + full instance definitions + public/hidden test splits (checksummed).
3. All prompts (system/user) and full transcripts for every submission, revision, and self-report probe.
4. Environment logs: every execution, test outcome, error class, workspace version, timestamp.
5. Per-participant metadata: model ID, API parameters, token counts per phase, arm, stratum, seed.
6. Analysis code + raw scores; a SHA-256 manifest of all artifacts.
7. A null-arm sanity check: rerun S on Family-A tasks after the experiment to verify no drift (model updates) — if drift detected, results are flagged and re-collected.

## 10. What each outcome means (summary)

- **C > S′ ≥ S, with retention + hidden verification intact:** the tested CVI claim (§18) survives its first challenge for this task family — causal interaction produced verified adaptive capability that static reasoning, even with equal budget, did not. (Support for CVI; not proof of generality.)
- **C ≈ S′:** feedback/interaction adds nothing over matched private effort — the core CVI mechanism (action and consequence as evidence) is empirically inert here, severely weakening the framework's testable claim.
- **C > S′ but retention/transfer/hidden legs fail:** the trajectory produces in-context fixes, not the "durable, generalising, externally verified" capability CVI's definition requires — the strict CVI claim is falsified even though interaction has value.

**Deliberate non-guarantee:** the design makes CVI's victory hinge on three independent legs (retention, transfer, hiddenness), each of which has a plausible empirical failure mode. Nothing in the protocol presumes C wins.

## 11. Implementation notes (for a later implementing agent)

- Fully implementable in Python + any LLM API (OpenAI/Anthropic/self-hosted); ~200–400 API calls per participant; no robotics, no lab equipment.
- The environment is a deterministic interpreter (~300 lines); task generation ~200 lines; harness enforces access control (hidden tests unreachable by agent calls) and logs everything.
- Suggested pilot: one model, all three arms, K=4, small families — to tune difficulty into the 0.30–0.80 baseline band *before* pre-registration of the main run.
- Do not reuse instances across pilot and main runs; regenerate with fresh seeds.
